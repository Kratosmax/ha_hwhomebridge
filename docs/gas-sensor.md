隔离进程已实际生成插座及燃气的注册JSON：燃气产品、型号、名称及

这排除了本次序列化将PLC字段截断或拒绝的猜测，不能据此认定家庭绑定成功。
52项单测及配置、隐私、diff检查通过。后台采集证据在
`temp/gas-payload-audit/live/`；下文关闭实验记录为此前恢复过程。

因此未接入成功。已关闭本地 `gas_sensor_enabled`，停止重启时重复注册实验，
恢复已验收的统一插座基底库；未删除已有云端设备、网关身份或绑定。

已经查证 HA 状态读取、原生服务表布局、SDK 新增/同步/上线响应和官方
卡片资源可访问；这些证据不能证明设备已加入用户家庭或手机列表。
准确失败环节仍未知，需要实际设备列表描述或逐设备家庭绑定结果才能继续定位。
不再无依据地更换 SN、协议或重复要求刷新。私有证据及恢复检查位于
`temp/gas-trial-disabled/`，不进入仓库。

关闭后的独立检查通过：实际加载已验收插座基底，网关和四插座在线，
温湿度及门磁上报启用，原有非燃气设备身份保持，15次队列采样均为0。
该检查确认恢复后的后台状态，不声称燃气接入或新增手机验收成功。

采用官方 [2MXG 定义](https://smarthome-drcn.dbankcdn.com/device/guide/2MXG/2MXG.json)，
映射 `lumi.sensor_gas.mcn02` 的工作状态和 %LEL 浓度。正常、泄漏报警、
故障、寿命到期分别映射；预热、不可用和未识别状态不伪造“正常”。
浓度范围为 0～100 %LEL，等级阈值 8、15 来自官方定义。
桥接只读，拒绝自检和消音等命令，不用真实报警验证映射。

旧实验替换了槽 0，并把服务 ID 同时写入服务类型表；不得重新启用旧库。
新构建器 `tools/build_gas_candidate.py` 从已验证的统一插座库构建，沿用
修正后的 64 项 SDK 服务表输出布局，只替换槽 7 的元数据。槽 0～6
保持不变；槽 7 的前身是已退役的断路器，不能与活跃 PID008 同用。
该限制来自当前固定 amd64 二进制的 8 个品类槽位。

启用前必须确认当前全部 PID008 都已排除，所选插座都已完成迁移。
安装检查旧卡排除清单；运行时拒绝 PID008 注册，并在发现未排除的
旧断路器时阻止燃气注册。新候选和单台、双台批量服务表须先在独立
空网络命名空间内验证，不启动 SDK main 或注册设备。

本地开关 `gas_sensor_enabled` 默认关闭；开启时要求完整通过统一插座
库验证，失败时禁用燃气并恢复已验证的插座基底，再启动已有设备；
不能回退到旧的燃气候选。`gas_sensor_registered` 在确认已有云端记录后
设为true，后续重启仅上线，不反复声明新增；它不表示所有显示/报警场景验收通过。
两项配置均只放在 HA 本地设置中，不保存个人实体和身份到源码。

2026-10-18：新候选隔离验证通过，只修改 121 字节元数据，槽 0～6
元数据不变。首次手机复测仍无燃气设备，原有设备正常。不能把
燃气三项上报返回 0 当成接入成功。

进一步隔离测试使用实际 SDK 状态更新函数和合成注册表，确认“新增3，
紧接上线1”会在调度前把新增覆盖成上线。燃气首次接入和重试现仅提交
新增，已经验收后重启仅上线；其他品类启动逻辑保持原样。新增真实注册
完成码记录，不再仅记请求已提交。48 项单测通过；部署后燃气新增调用
完成码为 0，捕获单设备绑定请求及云端新增成功日志，原有设备身份保留、
网关和四插座在线。日志未标明设备 SN，手机验收仍待确认，尚不能把
该覆盖实验认定为燃气缺失的唯一原因。

手机复测仍无设备、原有设备正常，因此继续对照新身份：本地可选
`gas_sensor_identity_version` 为 1 或 2，默认 1 沿用原 SN。2 根据原 HA
device_id 和固定产品标签派生新的稳定 SN，只作用于该燃气型号，
不更改其他设备身份，也不删除旧实验记录。启用 2 前独立只读检查确认
新 SN 尚未存在于 SDK 注册表。此对照用于区分旧注册记录与产品绑定问题，
不新增适配器或改变产品定义。SDK 日志只补存设备索引和数值状态，
不保存设备编号或请求正文到公开源码。对照版已部署：新身份对应的
SDK 设备索引收到新增、信息同步和上线响应，非燃气设备身份保持不变，
网关、四插座及队列检查正常。响应日志中的 status 是 SDK 队列阶段，
不是云端错误码；手机卡片是否出现仍待验收。

私有部署清单、备份和结果在项目 `temp/gas-v2/`，不进入公开仓库。
试验失败时按清单恢复这次修改的文件及本地配置并重启，不删除绑定、
网关身份或已有云端卡片。上次试验影响原有设备离线的准确原因尚未查明，
不能仅凭本轮发现的元数据错误把因果归于某一项。
