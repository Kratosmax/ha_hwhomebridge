# 本地温湿度计测试适配

该改动尚未发布；本机已由用户确认设备出现，换算修正后的温度、湿度都正确。支持 `miaomiaoce.sensor_ht.t2`，使用华为官方 [113D 产品定义](https://smarthome-drcn.dbankcdn.com/device/guide/113D/113D.json)。目前只映射温度和湿度，不推导电池低电量告警，也不修改其他房间空调的室温来源。

113D 的线上字段是整数，但其实际H5卡片会将两个字段都除以100再显示一位小数：23.8℃必须发送2380，95%必须发送9500。官方Profile的文字单位与实际卡片不一致，不能只按文字描述直接发送读数。该换算已查实于官方 `h5_001/static/js/app.9038352e71de3e78d353.js` 中的 `airDetector.temperature/100`、`airDetector.humidity/100` 及历史记录 `scale:.01`；未换算时用户实测为0.2℃、0.9%。未知、离线、无效数和超出物理读数范围的值不填默认值。此设备只读，不接受开关或其他设备控制命令。

在 HA 本地 `hwhomebridge_local.json` 中设置 `"thermohygrometer_enabled": true`，默认关闭。当前测试接在已有 amd64 空调扩展后，需要该扩展启用；不是所有架构通用的发布版本。

候选库保留现有空调槽及另外六个槽，只替换未使用的压力传感器槽3，因此不能同时使用原压力产品。启动部署前必须检查原压力设备未使用该槽。已有设备SN算法及网关绑定保持不变。

`tools/build_thermohygrometer_library.py` 使用固定源哈希和有前置字节检查的补丁重建候选库。首次加载前已在 NAS 单独进程、隔离网络命名空间中验证单设备/批量注册元数据和全部服务名；没有在检查进程中启动SDK、读取网关绑定或注册设备。其他七槽完整对照未变。

温湿度注册等待原空调初始化结束，沿用原设备发现流程对新旧设备的判断：首次接入发送新增与在线，重启后已有设备只发送在线。等待期间仅记住真正的新设备请求，避免每次重启都重复宣告新增。延迟上报避免和原SDK的批量注册冲突。`thermohygrometer_diagnostics` 只读返回绑定读数、阶段和有界查询/上报记录，SDK返回0不能替代手机App验收。

2026-10-18：修复启动时无条件发送新增状态的问题。本机重启诊断仅出现status=1，温湿度计SN保持，上报恢复；用户确认NEW已清除、原有设备正常。再次重启后不重新出现NEW仍可在后续维护时复核，不为这一项连续重启。

本地验收：先确认HA和SDK中的温湿度一致，再在智慧生活核对设备卡片与读数。本次用户已完成设备卡片与温湿度显示验收；独立脚本另核对了旧设备身份、空调身份、网关在线及部署文件哈希。

回滚：关闭本地 `thermohygrometer_enabled` 并重启HA，会恢复原空调候选库及压力槽定义；不要覆盖或删除网关身份文件。重新启用同一适配仍沿用同一个HA设备SN。
